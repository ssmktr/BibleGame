# 구약 / 신약 순서 맞추기 PRD

> 본 문서는 [구약_신약_순서맞추기.md](../구약_신약_순서맞추기.md) 기반의 세부 PRD 입니다.
> 상위 흐름(시작 화면 → 게임 선택 화면)은 [기획서_PRD.md](기획서_PRD.md) 를 참고하세요.

---

## 1. 개요 (Overview)
성경 66권(구약 39권 + 신약 27권)의 책 이름을 카드로 만들어 무작위로 섞은 뒤, 드래그 앤 드롭으로 정경 순서대로 맞추는 미니게임입니다. 클리어까지 걸린 시간을 기준으로 랭킹에 등록할 수 있습니다.

## 2. 라우팅 / 경로
- 게임 진입 : `/games/old-new`
- 게임 플레이 : `/games/old-new/play?type=old | new`
- 랭킹 : `/games/old-new/ranking`

## 3. 화면 구성 (Screens)

### 3.1 게임 초기 화면 (Entry)
| 항목 | 내용 |
|---|---|
| 위치 | `/games/old-new` |
| 중앙 UI | **구약 시작** 버튼, **신약 시작** 버튼, **랭킹** 버튼 (3개) |
| 상단 우측 | 게임 종류 선택 화면(`/select`)으로 이동하는 버튼 |
| 상단 우측 동작 | 클릭 시 "정말 가시겠습니까?" 확인 팝업 → "예" 선택 시 `/select` 로 이동 |

### 3.2 게임 플레이 화면 (Play)
| 항목 | 내용 |
|---|---|
| 위치 | `/games/old-new/play?type=old\|new` |
| 상단 중앙 | 타이머. 진입 시 0.00초부터 카운트업 (랭킹 등록용 데이터) |
| 상단 우측 | 게임 종류 선택 화면 이동 버튼 (확인 팝업 동일) |
| 본문 | 선택한 testament에 따라 **구약 39권** 또는 **신약 27권**을 풀네임(약자) 형식의 카드로 만들어 무작위로 섞고 **3열(컬럼) 그리드** 로 배치 |
| 카드 표기 | 예 : "창세기(창)", "마태복음(마)" |
| 카드 동작 | 드래그 & 드롭. **두 카드의 위치를 서로 교환(swap)** |
| 하단 | **제출하기** 버튼 |

### 3.3 결과 처리 (Submit)
- 제출하기 클릭 시 각 카드가 정답 위치인지 채점하여 **맞은 카드는 정답 표시(예 : 초록)**, **틀린 카드는 오답 표시(예 : 빨강)** 를 한다.
- **부분 정답** : 화면 이동 없이 사용자가 계속 카드를 옮겨 다시 제출할 수 있다. 타이머는 계속 흐른다.
- **전체 정답** : 닉네임 입력 팝업을 띄운다.
  - 닉네임 입력 후 **완료** 버튼을 누르면 타이머를 정지하고 랭킹 화면(`/games/old-new/ranking`)으로 이동한다.
  - 랭킹 등록 성공/실패 여부를 토스트 또는 안내 메시지로 표시한다.

### 3.4 랭킹 화면 (Ranking)
| 항목 | 내용 |
|---|---|
| 위치 | `/games/old-new/ranking` |
| 구성 | 구약 / 신약 **각각의 랭킹 탭(또는 분리된 표)** 을 함께 노출 |
| 페이지네이션 | **10행 × 3페이지 = 총 30개** 등록 가능 (구약/신약 각각) |
| 정렬 | 클리어 소요 시간 **오름차순** (작을수록 상위 랭크) |
| 표시 컬럼 | 순위 / 닉네임 / 플레이 시간 (mm:ss.ss) |
| 상단 우측 | 게임 종류 선택 화면 이동 버튼 |

## 5. 기능 요구사항 (Functional Requirements)
- FR-1. 초기 화면에서 **구약 시작** / **신약 시작** / **랭킹** 3개 버튼을 노출한다.
- FR-2. 게임 진입 시 선택한 testament(구약 39권 또는 신약 27권)의 카드 배열을 **균등 분포로 랜덤 셔플**하고 **3열 그리드**로 배치한다. (우연히 정답 순서가 나오면 다시 셔플)
- FR-3. 카드 라벨은 `풀네임(약자)` 포맷으로 표시한다.
- FR-4. 상단 중앙 타이머는 게임 플레이 화면 진입과 동시에 0부터 동작하며, 0.01초 또는 0.1초 단위로 갱신한다.
- FR-5. 카드는 마우스/터치 모두에서 드래그 가능해야 하며, **두 카드를 서로 swap** 한다.
- FR-6. 상단 우측 "나가기" 버튼 클릭 시 확인 팝업을 띄우고, "예"를 선택해야만 `/select` 로 이동한다. 그 외의 경우 현재 상태(순서, 타이머)는 유지한다.
- FR-7. 제출 시 각 카드의 정답/오답을 시각적으로 표시한다.
- FR-8. 전체 정답이 아닐 경우 게임은 그대로 진행되며 타이머도 계속 흐른다.
- FR-9. 전체 정답 시 닉네임 입력 팝업을 띄우고, 완료 버튼 클릭 시 타이머를 멈춘 후 랭킹 등록을 시도한다.
- FR-9-1. 닉네임 입력 시 비속어 체크를 수행하며, 비속어가 포함된 닉네임은 등록을 거부하고 안내 메시지를 표시한다.
- FR-10. 랭킹은 구약/신약 **각각 30개**까지 저장한다. 31번째 시도부터는 기존 랭킹의 최하위보다 빠를 때만 등록되고, 최하위는 밀려난다.
- FR-11. 랭킹 화면은 10행 × 3페이지 페이지네이션을 지원하며, 구약/신약 탭을 분리한다.

## 6. 데이터 / 저장
- 랭킹 저장은 **localStorage** 를 1차 저장소로 사용한다.
  - 키 예시 : `ranking:old-new:old` (구약), `ranking:old-new:new` (신약)
  - 각 항목 : `{ rank?: number, nickname: string, timeMs: number, createdAt: ISOString }`
- 닉네임 길이는 1~10자, 공백 트리밍 후 비어있으면 등록 불가.
- 닉네임 비속어 체크 후 비속어 포함 시 등록 불가.

## 7. UX / 접근성
- 카드는 충분히 큰 터치 영역을 확보하되, 66개를 3열로 배치하므로 모바일에서는 **세로 스크롤**을 허용한다.
- 카드 간 드래그 거리가 멀 수 있어, 드래그 시 자동 스크롤(auto-scroll) 동작을 지원한다.
- 색각 보조 : 정답/오답 표시는 색상 외에 아이콘(✓ / ✗)을 함께 사용한다.

## 9. 기술 스택 메모
- 드래그 & 드롭 : `@dnd-kit/core` + `@dnd-kit/sortable` 권장. 3열 그리드 + 66개 아이템에서 성능/접근성 양호.
- 상태 관리 : 페이지 단위 `useState` 로 충분.

## 10. 오픈 이슈
- 3열 그리드에서 **읽는 순서**를 어떻게 정의할지 명시 필요.
  - 옵션 A : 좌→우, 위→아래 (행 우선) — 일반적
  - 옵션 B : 위→아래, 좌→우 (열 우선) — 책 목록 정렬 시 자주 사용
  - 본 PRD는 **옵션 A(행 우선)** 를 기본으로 가정. 추후 확정 필요.
- 한 화면에 66개 카드를 한 번에 보여줄지(스크롤), 페이지를 나눌지 사용자 테스트 필요.
- 난이도 옵션(구약만 / 신약만 / 전체) 추가 여부.
